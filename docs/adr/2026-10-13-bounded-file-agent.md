# 资料研究 Agent 与图文联合问答

日期：2026-10-13。范围：本地 `ai-tool-chat` 实现；不代表生产部署或真实模型验收。

## 决策

沿用 Task -> Step -> Skill 与持久 SSE 事件，在文件附件场景增加显式选择的
`enableTools: true` 模式。服务端仍先验证账户文件归属与文件版本，再选择
`file-agent`。模型使用兼容 Chat Completions 的流式 function calling，
工具参数完整接收、正常结束并校验后才执行。

仅允许 `search_files` 与 `read_file`，目录 ID 为本任务局部的 `f1` 等。
工具不能访问任意文件路径、网络、其他账户或未附加的资料。文件名与原文作为
不可信数据进入提示词。允许模型根据工具观察继续检索；没有可引用依据时直接
结束，不能用通用知识冒充文件结论。

最多两轮工具决策、每轮两个工具，另保留一次最终回答。管理员把调用上限设为
1 时使用已有单次文件问答。所有模型调用复用预算预留与结算，不提高既有
3 次调用 / 16000 token 默认上限。工具决策输出上限 600 token；
每个原文片段至多 420 个 UTF-16 单位且至多 700 个 UTF-8 字节，累计格式化
证据至多 4000 字节。实际剩余额度不足时明确失败，不静默重试收费请求。

最终回答通过既有文本 SSE 生成。引用检查只检查来源标记是否属于本次原文、
是否缺失，不证明语义蕴含或答案质量。格式失败保留部分结果并标记任务失败，
不会标记为成功。推理字段仅用于上游工具续轮，不发送给浏览器。

真实供应商验收发现原兼容解析器把 `reasoning_content` 当作答案后备字段，
已移除该映射；推理 token 仍计入用量。支持 `thinking: { type: "disabled" }`
的供应商可显式设置 `AGENT_DISABLE_THINKING=true`，仅对资料研究的决策与
回答关闭独立推理输出，避免耗尽有限的工具决策预算。默认不发送这一供应商
选项，普通聊天与图文回答不受该开关影响。

工具执行转为现有 Step 事件，复用历史 `mcp` 类型以保持前端和旧记录兼容；
这里并未启用外部 MCP 服务。步骤保存工具名、状态与片段数量，不保存原文参数。
断线恢复只读取已持久化事件，不重启 Agent。

普通模式允许图片与文件共同输入：先检索文件，再把原文依据、问题与图片交给
视觉模型，提示其区分图片观察和文件引用。图片不进入文件 Agent；混合附件时
不显示资料研究开关。视觉模型仍须独立配置，文本模型名称不能证明视觉能力。

## 取舍

保留现有词法检索，不引入向量数据库、重排服务或多 Agent 编排。小范围资料
研究可以先验证任务闭环；关键词召回不足、长文覆盖与大知识库索引仍需后续
基于真实问题评测。所有片段均为局部依据，不宣称完整阅读整份文件。

## 验证入口

- `pnpm check`：前端与 Worker 的 lint、类型、构建、测试与部署 dry-run。
- `pnpm test:server`：Node/SQLite、实际上传解析、Agent 用量与持久 SSE。
- `fileAgentSkill.test.ts`：跨文件工具观察、取消、预算、无依据、错误引用。
- `toolCallAccumulator.test.ts`：碎片拼接、数量限制、非法参数及重复 ID。
- `multimodalSkill.test.ts`：图片与文件依据进入同一次视觉请求。

自动化模型输出均为离线响应或开发模拟，不能据此声称当前线上模型支持
function calling、检索质量提高、成本降低或生产验收完成。
