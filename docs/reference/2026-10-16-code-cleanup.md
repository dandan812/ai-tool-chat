# LLM 平台代码精简与规范统一

日期：2026-10-16，Asia/Shanghai。本次只修改本地源码，不部署、不迁移数据、不调用付费模型。
目标是减少阅读时需要理解的无效模块，同时统一前端、共享业务和 Node 服务规范。

## 覆盖范围

| 领域 | 已核对的入口与契约 |
| --- | --- |
| 前端 | main、Chat、Store、sessionTasks、请求管理、输入、上传、主题；保留现有页面和交互 |
| HTTP 与运行环境 | Worker 路由、Node server/http/runtime/build；保留 Node 和 Worker 两种适配 |
| 任务与数据 | DurableTask、TaskRepository、执行和用量；保留存储字段、事务、幂等、游标、取消和中断策略 |
| 账户与文件 | 账户目录与业务分派、上传服务、文件归属与租约；不删除校验和隔离 |
| 模型与检索 | 能力路由、文件问答、受限资料工具、原文检索与模型流；保留现有输入、来源和预算 |
| 工具与支持 | 静态导入图结合全仓库符号搜索核对旧工具、包装和类型；测试改为直接覆盖现行入口 |
| 工程与文档 | package scripts、ESLint、Prettier、CI、README、阅读指南和当前 ADR；历史决策保留 |

格式统一覆盖源码、测试和工程配置。未逐项重构仍在使用的算法、数据库适配、
CSS 和页面模块；它们只进行格式处理，并比较格式归一后的内容以排除额外手改。
线上状态、真实模型回答质量、外部私有脚本和生产负载不属于本轮验证范围。

## 实际变化

以修改前源码快照为基线，而非包含更早开发历史的 Git HEAD：

- 删除 28 个没有生产消费者的旧源码、专属测试和工具文件；另将前端格式配置迁至根目录。
- 151 个保留文件在使用同一 Prettier 配置归一后内容一致，只有格式变化。
  账户、上传、任务持久化与恢复、Node HTTP / SQLite / 文件存储实现均属此类。
- 实质修改集中于前端配置与类型、自适应输入、Skill 选择和上下文、
  文件处理的旧包装及对应测试。正文检索和现行 prompt 内容保留。
- 新增共享格式配置、Node ESLint 入口、输入高度回归测试与本记录。
  未增加依赖，也没有修改锁文件。

格式化会将原先单行的大对象展开，原始行数不适合直接代表复杂度变化。
本轮收益主要是减少需要追踪的模块和无效接口，没有通过压成单行缩短业务代码。

## 已有故障修复

修改前 `pnpm check` 的前端 307 个断言通过，但主题过渡定时器在测试文档销毁后
再次查找全局 document，产生未捕获错误，导致命令失败。
`applyThemeAttribute` 改为捕获它实际修改的根节点，延时只清理该节点。
新增回归检查在全局 document 消失后仍能清理原节点。
